# 串連系統 v2.2 — 人工參數方法論

> 「**主管排序決定方向，等價關係決定初始尺度，測資結果決定調整幅度，敏感度分析確認穩定性。**」

本系統的人工權重並非由開發者任意指定，而是經過五階段流程設計：

```
主管訪談 → 等價關係 → 弱先驗 → 測資校準 → 敏感度確認
```

每一階段都能對應到具體的設計動作與可審查的證據。

---

## 為什麼需要這份文件？

本系統有 **3 組人工權重**：

| 模組 | 權重參數 | 數量 |
|---|---|:---:|
| 員工負載分析 | 案件 / 卡點 / 交接 / 被提及 | 4 個主權重 + 衰減序列 |
| 組織健康度雷達 | 6 維度權重 | 6 個 |
| BM25F 智能搜尋 | 6 欄位權重 | 6 個 |

合計約 16 個人工參數。每個都能用這套五階段流程說明：「為什麼是這個數字？」

---

## 五階段方法論

### ① 主管訪談 — 決定方向

**問題**：哪個訊號比較重要？

**作法**：問主管「**這些訊號，你心中的重要性排序是什麼？**」

**員工負載排序：**
```
卡點 > 案件 > 交接 > 被提及
（影響半徑 > 直接負擔 > 中介工作 > 涉入度）
```

**BM25F 欄位排序：**
```
標題 > 摘要 > Tag > 負責人 > 內文 > 留言
（資訊密度由高到低）
```

**健康度 6 維排序：**
```
流動性 > 卡點 = 成員健康 > 溝通 = 決策 > 負載均衡
（對組織存續的影響度）
```

**文獻錨點：**
- Andy Grove《High Output Management》— 管理時間單位 2 週
- Edmondson《The Fearless Organization》— 溝通+心理安全為核心
- McKinsey OHI 9 維度模型 — 健康度維度選擇依據

---

### ② 等價關係 — 決定初始尺度

**問題**：「一件 A 大概等於幾件 B？」

**作法**：把抽象重要性翻成具體比例。

**員工負載：**
> 「**一件卡點大概等於 2~3 件普通案件**」 → 取 2.5

| 等價關係 | 解讀 |
|---|---|
| 1 個卡點 ≈ 2.5 個案件 | 卡點不只影響自己，還擋住別人 |
| 1 個案件 ≈ 2 個被提及 | 自己做事比被 cc 重很多 |
| 1 個案件 ≈ 1.25 個交接 | 交接有部分責任不在自己 |

**BM25F 欄位：**
> 「**標題 1 次命中 ≈ 內文 5 次命中**」 → 比例 5:1

| 等價關係 | 解讀 |
|---|---|
| 標題 1 次 ≈ 內文 5 次 | 標題濃縮整個案件意圖 |
| 摘要 1 次 ≈ 內文 4 次 | 摘要是精煉版內文 |
| Tag 1 次 ≈ 內文 2 次 | 結構化但訊息稀 |

---

### ③ 弱先驗 — 不要一開始就放大膽

**問題**：根據排序先給小幅差距，避免過度自信

**作法**：依排序給小差距，**讓資料來把它撐開或合攏**

**員工負載弱先驗版本（v0）：**
```
卡點 1.3、案件 1.2、交接 1.1、被提及 1.0
```

差距小、方向對、不過度承諾。

**理論依據**：這就是 Bayesian 統計的 **weak prior**（弱先驗）概念 — 在沒有強證據前不要把分佈設太尖。

**vs 強先驗（容易出問題）：**
```
卡點 5.0、案件 3.0、交接 1.5、被提及 1.0   ← 一開始就放大差距
```

如果排序錯了，強先驗的錯誤代價更大。

---

### ④ 測資校準 — 決定調整幅度

**問題**：用 SEED 跑，看實際分數對不對

**作法**：用 SEED data + 極端測資跑排序，看哪些案例被低估／高估，然後調整

**員工負載校準過程（弱先驗 → 收斂版本）：**

| 版本 | 卡點 | 案件 | 交接 | 被提及 | SEED 觀察 |
|:---:|:---:|:---:|:---:|:---:|---|
| v0 (弱先驗) | 1.3 | 1.2 | 1.1 | 1.0 | 林聿平（5 卡點）分數 5.8 ← 太低 |
| v1 | 1.5 | 1.5 | 1.0 | 1.0 | 林聿平 7.2 ← 還不夠 |
| v2 | 2.0 | 1.8 | 0.9 | 1.0 | 林聿平 9.5 ← 接近過載線 |
| **v3 (收斂)** | **2.5×1.5** | **2.0** | **0.8** | **1.0** | **林聿平 10.5 ← 觸發 high 級別** ✓ |

**校準錨點：**
```
極端 A：5 個極高風險卡點員工 → 應 ≥ 12 分 (overload)
極端 B：1-2 案件普通員工 → 應 6-14 分 (normal)
極端 C：無活動新進員工 → 應 ≤ 5 分 (low)
```

**這層不是「自由地調權重」 — 是「在等價關係的比例範圍內，找到讓三個極端案例落到正確等級的乘數」。**

---

### ⑤ 敏感度確認 — 確認穩定性

**問題**：萬一權重錯一點點，結論會崩嗎？

**作法**：把權重 ±10%~20% 隨機擾動，跑 500 次，看 Top-N 排名變不變

**真實實驗結果**（員工負載權重）：

| 擾動幅度 | Top-3 名單穩定 | Top-5 名單穩定 | Spearman ρ |
|:---:|:---:|:---:|:---:|
| ±10% | **99.4%** | 99.2% | 0.998 |
| **±20%** | **93.4%** | **95.8%** | **0.995** |
| ±30% | 89.8% | 93.5% | 0.989 |
| ±50% | 83.6% | 89.7% | 0.977 |

**程式碼**：`scripts/sensitivity_analysis.ts` ── 任何人可重跑

```bash
npx tsx scripts/sensitivity_analysis.ts
```

**結論**：
- Top-3 在 ±20% 擾動下 93.4% 穩定 → **系統不依賴精確權重**
- Spearman ρ = 0.995 → 排名相關性接近完美
- 證明模型靠的是「**排序原則**」而非「**精確數字硬湊**」

## 方法論的弱點（誠實揭露）

| 階段 | 弱點 | 補救 |
|---|---|---|
| ① 排序 | 文獻可能不適用本領域 | 預留多文獻交叉參照 |
| ② 等價 | 等價關係本身仍主觀 | 寫成文件、可逐條挑戰 |
| ③ 弱先驗 | 「弱」的程度沒有客觀標準 | 用 Bayesian 標準作法（差距 ≤ 30%） |
| ④ 校準 | SEED 是自編的，有 self-validation 風險 | 用極端錨點 + 多測資 |
| ⑤ 敏感度 | 證明 robustness 不證明 correctness | 老實承認 — 需 ground truth 補上 |

**整體結構性弱點：** 缺乏真實 ground truth → 所有層的「合理性」都建立在團隊內部直覺。

## 最佳作法（Future Work）

```
現狀（我們）                              最佳作法
─────                                  ─────
① 業界文獻                ──→            5+ 真實主管訪談
② 團隊內部等價             ──→            3-5 位主管獨立標註 + Cohen's κ
③ 弱先驗 (1.3:1.2:1.1)    ──→            同（這層不依賴真實資料）
④ 自編 SEED               ──→            真實 6-12 月歷史 + Grid/Bayesian Search
⑤ ±擾動 500 次            ──→            + Cross-validation + MAP@K / NDCG@K
                          ──→            + A/B test + Online Learning
```

**差距**：ground truth。是錢買來的，不是腦力換得到的。

**設計取捨**：本系統選擇「**可解釋人工權重**」而非「**機器學習自動學權重**」 — 因為使用者（主管）需要對員工說明評分依據，黑箱模型在管理場景不適用。
